MISSION DOSSIER

The Flight Plan

The full plan for a one-week advanced AI course on Google Cloud: what learners will be able to do, how every hour is spent, how progress is measured, and how to run it without surprises.

🗓️

Format

5 days × 8 hours (09:00–17:00), in person or live virtual. About 70% hands-on. Teams of 2–3 for boss battles and the capstone.

🎯

Audience

Data scientists, ML engineers and software engineers moving into AI. Comfortable with Python and SQL, and familiar with basic ML concepts.

🧰

Platform

Google Cloud, specifically BigQuery and Gemini Enterprise Agent Platform (formerly Vertex AI), with Cloud Run, Cloud Build and Model Armor.

Learning outcomes

By Friday, every learner can…

  1. Select the right technique for a problem (boosted trees, forecasting, clustering, LLM prompting, RAG, agents or fine-tuning) and justify it on cost, latency, accuracy and explainability.
  2. Build and explain classical models in BigQuery ML, including leakage-free feature engineering and Shapley explanations.
  3. Forecast with ARIMA_PLUS and the TimesFM foundation model, and decide between them with a backtest.
  4. Operationalize models with pipelines, experiment tracking, a registry, endpoints, a feature store, monitoring and CI/CD.
  5. Engineer Gemini applications with structured output, multimodal inputs, function calling, grounding and context caching.
  6. Generate images and video responsibly with Nano Banana and Veo/Omni models.
  7. Retrieve knowledge with embeddings, BigQuery vector search and RAG Engine.
  8. Build multi-agent systems with ADK 2.0, connect them to tools over MCP and to each other over A2A, and deploy them to Agent Runtime with Memory Bank.
  9. Tune Gemini with supervised fine-tuning and self-host Gemma 4 on Cloud Run GPUs with vLLM.
  10. Evaluate generative and agentic systems with autoraters, rubrics and trajectory metrics.
  11. Defend AI systems with Model Armor, least-privilege identities and red-teaming.
  12. Engineer cost with model routing, caching, batch inference and budgets.

Design principles

Why it's built this way

🔁

One continuous story

Artifacts from one day feed the next. Learners see a system grow instead of 30 disconnected demos.

⚖️

Classical vs. generative judgment

Every day asks "what's the cheapest thing that works?" Learners leave able to say no to an LLM when a tree is better.

🧪

Show, then struggle

Labs are scaffolded with code and expected outputs. Boss battles are open-ended so learners have to transfer the skill, not copy it.

🎮

Gamified momentum

XP, ranks, badges and boss HP bars turn a long week into a campaign. Retrieval-practice quizzes close every day.

🛡️

Production realism

Cost, IAM, evaluation and security are woven through every day, not saved for a single "best practices" slide.

🧭

Drift-proof skills

APIs change monthly. "API drift check" callouts teach learners to read schemas, check versions and adapt, which outlasts any single SDK release.

Instructor runbook

Running the mission without surprises

📅 T-14 days

  • Provision projects (one per learner) under a folder with budgets.
  • Request Cloud Run L4 GPU quota and Gemini throughput headroom for the class size.
  • Check org policies: service account creation, external IPs, allowed regions.
  • Re-verify every model ID on the model-versions page.

📅 T-7 days

  • Dry-run every lab end to end in a fresh project and update any API-drift spots.
  • Send learners Launch Prep with a "complete by T-1" deadline.

📅 T-1 day

  • Check who completed Lab 0.1 and fix stragglers.
  • Pre-build a "rescue" project with Day 1–4 artifacts in case someone falls behind.

🎙️ Daily rituals

  • 09:00 "Mission status" check-in: XP leaderboard and yesterday's boss winners.
  • Each lab: the instructor demos step 1 live, then circulates. Fast finishers take stretch goals or help others.
  • Boss battle: put a countdown timer on the projector, play music, let teams call out "damage dealt".
  • 16:50 Debrief quiz, then everyone runs cleanup together.

🔥 Known failure modes

  • Dataset location mismatch (US vs us-central1) on Day 1.
  • 429s when 30 people hit Gemini at once. Teach backoff and stagger runs.
  • Agent Runtime deploys take minutes. Start them before the break.
  • GPU quota not granted. Use the Model Garden fallback or an instructor demo.
Adapt the mission

Variants

3 days

Compressed

Day 1 (Labs 1.1–1.3) + Day 3 (3.1–3.4) + Day 4 (4.3–4.6), with a mini-capstone. Drop MLOps to a demo.

Async

Self-paced

The site is self-contained. Learners progress at their own speed, XP is saved locally, and boss battles become weekly challenges with a peer review.

Advanced

Elite track

Swap the 2.4 Feature Store lab for distributed training on TPUs, and add ADK 2.0 graph workflows plus custom eval metrics to Days 4–5.
